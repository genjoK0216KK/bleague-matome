## 方針

1. 記事の種類で構図を変える（文字の差し替えだけを「新デザイン」とは呼ばない）。
   | 記事の種類 | type | 構図 |
   |---|---|---|
   | 試合結果 | game | 左右のチーム色＋大きなスコア＋活躍選手 |
   | 試合前（その日の対戦） | preview（新） | 開始時刻を大きく、対戦カード最大4つ。スコア・予想スコアは描かない |
   | 2チーム・選手の比較 | compare（新） | 項目ごとの1位選手と値を所属チームの色の棒で。記事の表の値だけ |
   | 移籍・契約 | transfer | 選手名が主役、旧所属→新所属 |
   | 速報・その他 | news | 見出しの種類を大きく、要点を最大3つ |
2. 数値・名前・日付は記事本文・表に書いた値だけを JSON に入れる。記事に無い値は書かない（推測で埋めない）。
3. 写真・ロゴ・他サイトの画像は使わない。有料APIや新しい認証は使わない。
4. 8・12・19時の更新とサムネ（**提案。本人の「毎回デザインを」の要望を満たしたとはまだ言えない**）：
   - 公開は従来どおり**毎回、記事HTMLとサムネの2ファイル**を送る（1ファイルだけにはしない）。
   - 案A（本人要望に近い）：毎回、その回の記事内容から JSON を作り直してサムネを生成する。
     内容が同じなら同じ SVG になる（同じものを送っても差分は出ない）。
   - 案B：8時は必ず作る。12時・19時は、記事の種類・主役・サムネに載せる値が変わった時だけ作り直し、
     変わらなければ既存のサムネをそのまま2ファイルの1つとして送る。
     判断用に、SVG 先頭のコメント `<!-- thumb: {...} -->` に JSON を残し、次の回はそれと比べる。
   - どちらを採るかは本人判断。いずれも「文字だけ差し替えた同じ型」を新デザインとは呼ばない。
5. 報告に「サムネ：作り直し（type=…）」または「サムネ：前回のまま（内容に変化なし）」を書く。
6. 確認できていない情報を、確認済みに見せない：試合前プレビューのカードには、記事で「未再確認」とした試合に
   `"flag": "未再確認"` を付ける。注記は記事の確認状況と同じ内容にする。

## 小さい画面での見え方（samples/thumb-20261022/thumb-compare-sheet.png）

- 記事先頭（375px 画面で 343×214）：新しい2案とも、対戦カード・選手名・値が読める。
- 一覧の小さいサムネ（132×84、スマホ 96×66）：現行の青い型も、試合前・比較の詳しい型も、細かい文字は読めない。
- 一覧向けに要素を3つ（種別・主役・一言）に絞った型 `simple` を追加した（見本：sample-simple-*.svg）。
  96px でも「試合前／比較」の種別と「10.22 4試合」「湘南 vs 山口」は判別できる。
  ただし同じ SVG が記事先頭にも使われるため、詳しい型と一覧向けの型のどちらを使うか（または両方を作り分けるか）は
  本人判断。作り分けには一覧の生成側の変更が要る（未実装）。
- 比較の型で、下端の注記（取得日・出場未確認）が右下の「バスケまとめ」と重なっていたのを別の行に分けた（回帰試験あり）。
- 色表（scripts/team_colors.json）に無いクラブ（湘南・山口・八王子・東京U など）は灰色系の代替色にした。
  色表にあっても暗い色のクラブ（例：横浜BC）は黒背景で色の帯が沈む。必要なら色表の調整が別途要る。
