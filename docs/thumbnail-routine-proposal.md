## 方針

1. 記事の種類で構図を変える（文字の差し替えだけを「新デザイン」とは呼ばない）。
   | 記事の種類 | type | 構図 |
   |---|---|---|
   | 試合結果 | game | 左右のチーム色＋大きなスコア＋活躍選手 |
   | 試合前（その日の対戦） | preview（新） | 開始時刻を大きく、対戦カード最大4つ。スコア・予想スコアは描かない |
   | 2チーム・選手の比較 | compare（新） | 項目ごとの1位選手と値を所属チームの色の棒で。記事の表の値だけ |
   | 移籍・契約 | transfer | 選手名が主役、旧所属→新所属 |
   | 速報・その他 | news | 見出しの種類を大きく、要点を最大3つ |
2. 数値・名前・日付は記事本文・表に書いた値だけを JSON に入れる。記事に無い値は書かない（推測で埋めない）。
3. 写真・ロゴ・他サイトの画像は使わない。有料APIや新しい認証は使わない。
4. 8・12・19時の更新とサムネ：
   - 8時（その日の最初の記事）：必ずサムネを作る。
   - 12時・19時で同じ日の記事を書き換えるとき：記事の**種類か主役（試合・チーム・選手）か、サムネに載せる値**が
     変わった場合だけサムネを作り直す。変わっていなければサムネは触らず、記事だけを公開する
     （公開は従来どおり最大2ファイル。1ファイルだけの公開も可）。
   - 判断のため、サムネ用 JSON の内容を SVG 先頭のコメント `<!-- thumb: {...} -->` に残し、次の回はそれと比べる。
5. 報告に「サムネ：作り直し（type=preview）」「サムネ：前回のまま（内容に変化なし）」のどちらかを書く。

```diff
+   - `pip install --quiet fonttools brotli`（失敗しても続行可。数字フォントが端末の字体になるだけ）
+     → `python3 scripts/thumbgen.py thumb.json thumb-daily-<YYYYMMDD>.svg`。thumb.json は公開しない。
+   - SVG の2行目に `<!-- thumb: <thumb.jsonを1行にしたもの> -->` を入れる。
+   - 同じ日の記事を更新する回（12時・19時）は、既存の thumb-daily-<YYYYMMDD>.svg の `<!-- thumb: … -->` と
+     今回の JSON を比べ、同じならサムネは作り直さず公開にも含めない（記事HTMLだけを公開する）。
+   - 最終報告に「サムネ：作り直し（type=…）」または「サムネ：前回のまま」を書く。
```

手順7（公開）の「2ファイルだけ」は「この2ファイル以内（サムネが前回のままなら記事HTMLだけ）」に読み替える一文を足す。
