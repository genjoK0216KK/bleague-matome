# 本番反映・復旧手順

## 実装済みの接続

`update.yml`の既存07:00/12:00/21:00/23:00 JSTを維持し、fetch.pyとbuild.pyの間で
`python scripts/update_match_features.py --season-year 2026`を呼ぶ。
明示season設定を次季移行時に検証して変更する。新資格情報は不要。

更新順は、現在IL、当日/前日の3リーグ結果、翌日の実日程、次戦プレビュー、3リーグの日付記事。
翌日に試合のあるリーグをプレビュー生成で優先する。
次戦探索の失敗を日次結果から分離。公式日程fallback先を翌日の試合と扱わない。

作業は一時ディレクトリで行い、許可したファイル名のHTML/SVGのみ公開rootへ反映。
raw captureとgeneration-reportは公開しない。管理JSONはdata/match_articlesへ保存する。
個別記事の管理一覧は候補と独立して永続化し、不完全取得後の撤回にも対応する。
特筆理由はdata/match-editorial.jsonの検証済み理由＋公式URLを各回使う。省略・空は特筆なし／撤回。
repoのroutine-promptに重複防止を追記済み。外部Claude定期実行の保存済みプロンプトは未変更なので、別途同期確認が必要。

## 失敗挙動

- IL取得失敗：前回JSONを保持し、HTMLに取得失敗警告。成功日時を更新しない。12時間超は閲覧時にも警告。
- 新規IL取得できず履歴もない：未取得表示。登録者ゼロと断定しない。
- 片リーグ結果失敗：途中版。既知試合が消えるなら以前の統合記事を保持。
- 完全取得後の試合なし訂正・特筆撤回：管理済み記事とSVGだけ削除。
- profile途中失敗：確認済みIL判定を保持、未照合は未確認と警告。
- 予算切れ：以降のHTTPを停止。取得できたページは更新、未取得は警告。既存ニュース・PREMIER集計とbuildは継続。
- CLIは部分失敗をActions warningと構造化ログへ出す。予期しない例外は失敗として終了する。
- 現在ILと抹消履歴の両方がある場合は現在IL優先。日付の年は推測しない。抹消だけでは出場確定としない。

## 時間・負荷

HTTPは各30秒timeout＋取得後2秒待機。同一実行内のURLは再利用。
全体120リクエスト・360秒の予算を持ち、残り32秒未満なら新規HTTPを始めない。
表記や完全一致名の照合後、未解決候補がある場合だけ公式PlayerIDプロフィールを取得する。
登録順序の最適化は照合の優先順のみで、文字種から同一人物を推論しない。

従来の1プレビュー＋当日結果の実測は15 GET・約35秒。全リーグ・11試合を含む場合は負荷が増えるため、公開前live-runログで生成数と予算内完了を確認する。
既存workflowは15分上限。新機能の360秒に加え既存fetch/buildの所要時間が必要。遅延日は一部未取得と表示し、次回再取得する。

## 公開手順

1. 機能ブランチを独立レビューし、全テスト、オンライン隔離生成、390/1280px描画、buildを検証。
2. 最新mainと比較し、既存自動ニュース更新を保持。公式capture・一時ツール・全量診断データは含めない。
3. 初回生成記事、injury.html、next-games.html、管理JSON、ナビ・一覧・sitemapを含める。offline/noindex検証版は公開しない。
4. GitHub remoteへ機能ブランチをpushしPRで確認後、承認済み公開依頼の範囲でmerge。ローカルoriginは元Claude checkoutなのでpush禁止。
5. GitHub Pagesのbuildと実URLのHTMLを確認。cron時刻は変更しない。

## Rollback

新機能のworkflow stepだけ無効化し、既存fetch/stats/buildとcronを維持する。
対象の機能コミットをrevertする。自動ニュース更新を巻き戻すhard resetを使わない。
管理JSONを参照して生成記事・SVGを直前の正常版と揃え、削除されたものも必要なら復元する。
新規IL/次戦ページを外す場合はナビリンクも戻す。
既存buildを再実行し、一覧・カテゴリ・sitemapの残存リンクを確認して通常の公開経路で反映する。
