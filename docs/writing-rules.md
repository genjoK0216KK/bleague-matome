# バスケまとめ 記事の文章ルール

元：Notion「Ghost Writer 記事制作 引き継ぎ書（X発信）」の「本人レビューによる最新の文章ルール（2026-10-12）」。
本人 2026-10-28「記事もちゃんと改行とか読みやすい文章にして」で、バスケまとめの記事にも同じルールを使う。
本人 2026-11-03「文章をもっと読みやすくしたい。改行とか」「注釈が多すぎる。引用元が〜とか」で、段落を短くし、注釈を減らした。
直した見本：`article-daily-20261103.html`（2026-11-03 に書き直し）。
事実・数字・出典は変えない。読みやすさだけを直す。

## 1文
- 1文に読点「、」は1つまで。2つ以上になったら、読点を削るのではなく、2文に分けるか言い換える。
- 1文は長くても60字くらいまで。長い文は分ける。
- 主語と順番をはっきり書く（例：「東京Uが主催し、江戸川区スポーツセンターで開催」ではなく「主催は東京Uです。会場は江戸川区スポーツセンターです。」）。
- 括弧（）の中に長い補足を入れない。補足は次の文に出す。

## 段落
- 1段落は1〜2文。3文以上になったら分ける。
- 短い段落を重ねてよい。スマホで3〜4行に収まるくらいが目安。
- 話題が変わるところで段落を分ける。

## 記事全体
- 主旨を1つに決める。リード（`p.lead`）の2〜3文で「何の記事か」「読むと何が分かるか」を書く。
- 作業の経緯は本文に書かない。「Web検索スニペットで」「12時台の再確認では」「WebFetchが名前解決で失敗」などは読者に関係ない。
- 未確認のことは、読者の判断に関わる時だけ「〇〇は未確認です」と本文で1回書く。関係ないものは書かない。

## 注釈を減らす（本人 2026-11-03）
- 本文に「〜で確認しました」「〜で一致しています」「当サイトが独自に集計」を書かない。根拠は出典欄だけで示す。
- 本文に「公式サイトをご確認ください」「変わる可能性があります」「保証するものではありません」などの念押しを書かない。注意書きは、記事の最後の免責（`div.note`「本記事は各公式発表・報道をもとに…」）1つだけにする。
- 予測の記事では「予測」と見出しに出せば十分。本文で何度も断らない。
- 更新したことの注記（`div.note`）は、記事の中で最新の1つだけ。変わった中身を1〜2文で書く（例：「19時に更新：10/30も同じ会場で試合があることを追記しました」）。古い注記は消す。
- Q&A は、読者が本当に知りたいことに答える時だけ置く。「この記事は予測ですか」のような断り書きのQ&Aは置かない。置く時は質問と答えを別の行に分ける。
- 確認した時刻・取得時刻・確かめ方は記事に書かない。ルーティンの報告にだけ書く。

## 出典欄
- 出典は閉じた形でまとめる：`<details class="sources"><summary>出典（N件）</summary><ul><li><a href="…" target="_blank" rel="noopener nofollow">媒体名：何の記事か（日付）</a></li>…</ul></details>`
- リンクの文字は「媒体名：何の記事か（日付）」。URLをそのまま文字にしない。見出しを引用する時は、実際の見出しと同じ時だけ「」に入れる。
- リンクの外に説明を書かない。取得時刻・「※検索結果で確認」なども書かない。
- 「？」「！」は一律に禁止しない。自然に伝わる場面では使ってよい。

## 確かめ方
公開する前に次を実行し、「指摘なし」になるまで直す。

```bash
python3 scripts/check_writing.py article-daily-YYYYMMDD.html
```

- 読点が2つ以上の文、3文以上の段落、作業の経緯の言葉、本文の念押し・確かめ方、2つ以上の更新注記を、場所と一緒に表示する。
- 出典欄は、URLをそのまま文字にしたリンクと、リンクの外の説明書きを表示する。
- 表の中と、記事の最後の免責1つは数えない。
