# Claude Code への依頼：バスケまとめ（basuke-matome.jp）のまとめ記事を増やす

## 背景
- リポジトリ: genjoK0216KK/bleague-matome（GitHub Pages、独自ドメイン https://basuke-matome.jp/ 、main ブランチ直下を公開）
- サイト名は「バスケまとめ」（2026-10-13 に「Bリーグ まとめ」から変更済み）。
- 仕組み:
  - `.github/workflows/update.yml` が1日4回（JST 7/12/21/23時）`scripts/fetch.py` → `scripts/build.py` を実行して自動コミット。
  - `fetch.py` は B.LEAGUE公式ニュースとバスケット・カウントのRSSから「見出し・URL・日付・出典」だけを `data/news.json` に保存（本文は保存しない方針）。
  - `build.py` は各HTMLの `<!-- AUTO:名前:START --> … <!-- AUTO:名前:END -->` の間だけを書き換える。`article-*.html`（手書き記事）は全件を読み込んで一覧化する。
  - 毎朝 claude.ai のルーティン「バスケまとめ_自動更新」（trig_01FYDJvMKt9jsViyiMvwvaHX）が記事を1本書いて GitHub コネクタで公開している。
- 目的: 日本のバスケの情報が少ないので、「まとめ記事」を読める量を増やしたい。
  - 対象は国内バスケ中心（B.LEAGUE、日本代表、Wリーグ、高校・大学、3x3 など）。
  - 海外は「日本人選手（八村塁・河村勇輝・富永啓生 など）」と「超有名選手（カリー、ヨキッチ など）」の話題だけ。それ以外のNBAネタは載せない。

## やること A：まとめブログの新着リンク集を作る

1. `scripts/fetch.py` に「まとめブログ」用の取得元を追加する（既存の `RSS_FEEDS` とは別リスト `MATOME_FEEDS`）。
   - 確認済みで使えるもの:
     - バスケまとめ・COM: `https://basketballbbs.com/?feed=rss2`（毎日更新、RSS 2.0）
     - NBAまとめ！: `http://nbama.blog.fc2.com/?xml`（毎日更新。FC2のRSS。形式は要確認）
   - 使わないもの: NBAスポーツ速チャン（2021年で更新停止）、Bリーグを盛り上げろ！千葉ジェッツまとめ（robots.txt で取得禁止）。
   - 国内バスケ寄りのまとめブログを追加で探し、RSSが取れて直近1か月以内に更新があり、robots.txt で禁止されていないものだけ足す（見つからなければ上の2つで可）。
   - 各サイトの robots.txt を尊重し、既存の `get()`（UA明示・2秒待機）を使う。
2. 絞り込みルール（最重要）:
   - 国内の話題（既存の `RELEVANT_RE` に加え、日本代表・Wリーグ・高校・大学・ウインターカップ・インターハイ・3x3・天皇杯・皇后杯 など）→ 採用。
   - 海外の話題（【NBA】やNBAのチーム名など）→ 日本人選手名か「超有名選手」名を含むときだけ採用。
   - 日本人選手リストとスター選手リストはファイル冒頭の定数にして、後から簡単に足せるようにする。
     - 日本人選手の例：八村塁 / 八村、河村勇輝 / 河村、富永啓生 / 富永、渡邊雄太 / 渡邊、馬場雄大、山崎一渉、ジェイコブス晶。
     - スターの例：カリー、ヨキッチ、レブロン、ドンチッチ、ウェンバンヤマ、ヤニス、デュラント、SGA / ギルジャス＝アレクサンダー、エドワーズ、テイタム。
   - アニメ・漫画、雑談、バッシュ紹介などバスケの試合・選手と関係ないものは落とす。
   - 本文は保存しない（見出し・URL・日付・出典名だけ）。
3. 保存先は新しく `data/matome.json`（既存 `news.json` と同じ形式・同じマージ方式・上限件数あり）。
4. `scripts/build.py` で表示する:
   - トップ（index.html）の「公式・メディアの新着」の下に、新セクション「ファンの反応・まとめブログ」を追加（`AUTO:MATOME` マーカー、10件程度＋「もっと見る」）。
   - 一覧ページ `matome.html` を新規作成（`news.html` と同じ作り。ヘッダー・フッター・CSSも共通）。
   - グローバルナビに「まとめ」を追加（全ページ共通のヘッダー。build.py が生成するページと手書き記事の両方）。
   - 各項目は出典ブログ名を表示し、外部リンクは `target="_blank" rel="nofollow noopener"`。既存の外部リンク項目（`.item.ext`）と同じ見た目でよい。
   - `sitemap.xml` に `matome.html` を追加。
   - about.html の運営方針に「まとめブログの新着見出しへのリンクを掲載している（本文は転載しない）」旨を1文追記。

## やること B：自作のまとめ記事を1日複数本にする

1. ルーティンが1日に複数本書けるよう、ファイル名を `article-daily-YYYYMMDD.html`（1本目）、`article-daily-YYYYMMDD-2.html`、`-3.html`、サムネを `thumb-daily-YYYYMMDD[-N].svg` とする。
   - build.py は `article-*.html` を全件読むので一覧には載るはず。同じ日付の記事の並び順（-2, -3 も正しく新しい順になるか）と、トップのヒーローやピックアップの選ばれ方を確認し、必要なら修正する。
2. ルーティンの新しい指示文（下の「ルーティン指示文（新）」）を、そのまま使える完成形で `docs/routine-prompt.md` に保存する。
   - ルーティン本体は claude.ai の「ルーティン → バスケまとめ_自動更新 → 編集」で人が貼り替える。Claude Code からは変更しない。
   - 指示文の変更点：
     - 1日3本（国内2本＋海外の日本人選手・スター1本。海外ネタが無い日は国内3本）。うち1本は、やることDの「話題まとめ」にしてよい。
     - タイトル末尾を『｜バスケまとめ』に変更。
     - 対象範囲は上の「目的」と同じ。
     - 3本をまとめて1コミットで公開する。

## やること D：5chで話題のネタからオリジナル記事を書く

ねらい：ファンの間で今なにが話題か（5chのバスケ関連スレで盛り上がっている話題）をネタ元にし、記事は自分の言葉で書く「オリジナル記事」にする。

1. 話題の把握
   - 5chのバスケ関連の板・スレ（例：B.LEAGUE、日本代表、高校バスケ、NBAの日本人選手スレ）の「スレタイ一覧と勢い」だけを、5chの規約・robots.txt・公式に許可された方法の範囲で取得できるか調べる。
   - 取得できない、または規約上グレーなら、5chは使わない。その場合は、まとめブログ（やることA）の見出しや各メディアのアクセスランキングで「話題」を判断する方式に切り替える。どちらにしたかを報告する。
2. 記事の書き方（ルーティンの指示文に組み込む）
   - 5chの書き込みを引用・転載しない（1行も載せない）。スレのURLや書き込み番号も載せない。架空のファンコメントや「名無しさん」風の発言を作らない。
   - 事実は必ず実在の報道・公式発表で裏取りし、出典ブロックに記載する（既存記事と同じ）。
   - 「ファンの間では○○の起用法をめぐって議論になっている」のように、話題の傾向を一般的な表現で一言添えるのは可。特定の書き込みの再現はしない。
   - 記事タイプ名は「話題まとめ」。カテゴリは既存の kekka / sokuho / iseki / data から選ぶ。
3. 本数：やることBの1日3本のうち1本を、この「話題まとめ」枠にしてよい（話題が無い日は通常記事）。

## やること E：記事一覧のページ分け

- 2ページ目以降も sitemap.xml に入れる。canonical はそれぞれ自分自身。

## やること F：各記事にPV（閲覧数）を表示

## ルーティン指示文（新）のベース
現在の指示文をベースに、上記B-2の変更を加えた完成形を作ること。現在の指示文の要点：
- 編集者として GitHub: genjoK0216KK/bleague-matome（公開 https://basuke-matome.jp/ ）に記事を公開する。
- 公開の絶対ルール：
  - ダミー内容の push 禁止。
  - git push 禁止。必ず `mcp__GitHUB__push_files`（大文字）で1コミット公開する。
  - 403 のときは `mcp__GitHUB__create_or_update_file` で1ファイルずつ公開し、それも失敗したら Gmail 下書き『bleague routine publish result』に残す。
- 手順：
  1. 日付を取得する。
  2. article-iseki-august.html と thumb-iseki-august.svg を手本にする。
  3. WebSearch / WebFetch で複数ソースから裏取りする（bleague.jp, basketballking.jp, basket-count.com, sports.yahoo.co.jp/basket）。
  4. カテゴリを決める（kekka / sokuho / iseki / data）。
  5. 記事 HTML を書く（title 末尾、meta、og:url、style.css、header/nav/footer、breadcrumb、h1、pmeta、eyecatch、adbox、lead、h2、出典 rel=nofollow、免責、関連記事）。
  6. サムネ SVG を作る。
  7. `python3 scripts/build.py` を実行する。
  8. `git status --porcelain` で変更ファイルを把握する。
  9. `push_files` で公開する。
  10. 報告する。
- 注意：直近（10/12）のルーティン実行は RUN_ERRORED で失敗している。3本に増やすと実行時間が延びるので、1本ずつ書き上げてから最後にまとめて公開する流れにし、途中で失敗しても書き終えた分は公開できるよう指示文に入れること。
